The Walk-In · motion storyboard

Direction C (client choice, 24 Nov 2026): every scene on the home page stays. The work makes them one continuous walk through the restaurant, with each scene handing something to the next. This page is for sign-off before any scene is built.

How to read a scene: the frame is today's site at 1280 px. The blue dots mark what will move. The bar shows when each beat happens (scroll position through a pinned scene, or time for an intro). The table gives the exact change, timing and the motion token from src/styles/tokens.css.

Rules for every scene

  • Only the animation tools already in the project: CSS scroll and view timelines, anime.js, Motion, Lenis. No new library.
  • transform and opacity only, plus stroke-dashoffset for drawn lines. Responses to a tap or click take 200–600 ms, ease-out (--curve-out); things with weight land on --curve-stamp; scrubbed scenes follow the scroll.
  • Reduced motion: each scene shows its finished state (the "Calm" line). Pause motion stills every loop; tests/e2e/motion.spec.ts fails if one is missed.
  • Book is one tap away throughout: on phones, the dock stays up while scrolling down through the long scenes.
  • Budgets per scene: dropped frames under 2 % (npm run perf:budget), taps under 200 ms (npm run perf:taps), Lighthouse mobile ≥ 90, home JS on track for under 100 KB (new motion goes in CSS and small scripts, not new React islands).
  • Proof per scene: before/after at 375 and 1280, a short screen recording, and one line in audit/CHANGELOG.md.
